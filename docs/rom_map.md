# ROM map: Dragon Ball Z: The Legacy of Goku (USA), ALGE

8 MB (0x800000 bytes, 0x7A6418 used), SHA-1 `a3c8c76742f11fc6a3f6e3fcca20992458cac0b5`.
Offsets are ROM file offsets; add 0x08000000 for the bus address.
The byte-level classification (100% coverage) is `config/regions.yaml`, generated by `tools/bfdis/regions.py`.
Layout constants are in `config/game.json` (read by `tools/bfdis/game.py`) and `tools/assets/const.py`.

## Sections

| Range | Size | Section | Contents | Source in this repo |
|---|---|---|---|---|
| 0x000000-0x0000BF | 192 B | header | Entry branch, Nintendo logo, title `DBZ LGCYGOKU`, code `ALGE`, maker `70` | `asm/header.s` |
| 0x0000C0-0x000117 | 88 B | crt0 | ARM start-up: IRQ and system stacks, IME off, IRQ vector -> `IntrMain`, `bx` to `AgbMain` (0x08000274). No RW copy | `asm/crt0.s` |
| 0x000118-0x00EE53 | 59 KB | text | `IntrMain` (ARM, copied to IWRAM 0x03003BC0 by the game) and Thumb game code (C++), literal pools, switch tables; the ARM C library near the end (`__rt_sdiv` 0x0800E56C, `__call_via_rN` 0x0800E4A0) | `asm/code_*.s` |
| 0x00EE54-0x00EEBF | 108 B | ctorvec | `C$$pi_ctorvec`: 27 entry-relative offsets to static constructors | `asm/code_0800CDF4.s` |
| 0x00EEC0-0x00EED7 | 24 B | veneers | 2 armlink ARM->Thumb veneers (`ldr ip, [pc]; bx ip`) | |
| 0x00EED8-0x00F31B | 1 KB | vtables | base-relative C++ vtables | |
| 0x00F31C-0x00FE3F | 3 KB | text2 | more Thumb code | `asm/code_0800F31C.s` |
| 0x00FE40-0x7A6417 | 7.6 MB | rodata | strings, tables, 182 BIOS-compressed graphics streams (168 Huffman, 14 LZ77; 1.4 MB), 3 movie streams (custom codec, 3.5 MB), music and samples | `data/rodata_*.s` |
| 0x7A6418-0x7FFFFF | 359 KB | padding | 0xFF fill | `objcopy --pad-to --gap-fill 0xFF` |

There is no RW image: the game copies two routines into IWRAM itself (`IntrMain` from 0x08000138 to 0x03003BC0 and an ARM
routine from 0x08008840 to 0x03003D70).
